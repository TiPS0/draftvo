# Fix Swipe-Back Auth Bypass (bfcache Security)

> **Generated by `/agent-plan`**
> **Date:** 2026-08-21
> **Type:** bug_fix

---

## 1. Summary

After logout, the macOS 2-finger swipe-back gesture restores the authenticated home page from the browser's Back-Forward Cache (bfcache) without making a server request — bypassing the JWT session guard in `(main)/layout.tsx`. The fix adds two complementary layers of protection:
1. **Next.js Middleware** (`middleware.ts`) — intercepts every navigation at the edge and blocks unauthenticated access before any page renders.
2. **`pageshow` event listener** inside `AppLayout` — detects bfcache restoration at the client level and forces a session re-check, redirecting to `/login` if the session is gone.

---

## 2. Affected Screens & Components

- **[NEW]** `frontend/src/middleware.ts` — Edge middleware that checks for the `draftvo_session` cookie on all protected routes and redirects to `/login` if missing.
- **[NEW]** `frontend/src/app/api/auth/session/route.ts` — Lightweight `GET` endpoint that verifies the JWT cookie and returns `{ ok: true }` or `401`. Used by the client-side `pageshow` guard.
- **[MODIFY]** `frontend/src/app/_components/AppLayout.tsx` — Add a `useEffect` that listens for the `pageshow` event. When `event.persisted === true` (bfcache restore), call `GET /api/auth/session`. On 401, call `window.location.replace('/login')`.

---

## 3. User Flow (Step-by-Step)

### Normal logout flow (unchanged)
1. User clicks Logout in `SettingsModal`.
2. `POST /api/auth/logout` clears the `draftvo_session` cookie.
3. `window.location.replace('/login')` navigates to the login screen.
4. User is on `/login`.

### Swipe-back attempt — AFTER fix
5. User does a 2-finger swipe-back gesture.
6. **Middleware fires first (primary guard):** The browser makes a fetch for `/`. Middleware checks for `draftvo_session` cookie — it's gone → redirects to `/login`. Page never renders.
7. **If middleware was somehow bypassed (defense-in-depth):** bfcache restores the old `/` snapshot. The `pageshow` listener in `AppLayout` fires with `event.persisted === true`. It calls `GET /api/auth/session`. The response is `401` (no valid cookie). `window.location.replace('/login')` is called immediately. User is redirected back to login.

## 4. Technical Requirements

### Middleware (`frontend/src/middleware.ts`)
- Check `request.cookies.get("draftvo_session")?.value`.
- Define protected routes as: any path NOT starting with `/login`, `/register`, or `/api/auth`.
- If route is protected and cookie is absent → `NextResponse.redirect(new URL("/login", request.url))`.
- If route is public OR cookie is present → `NextResponse.next()`.
- **Important:** Do NOT validate the JWT signature in middleware (Edge Runtime has limitations). Only check for cookie presence. The full JWT verification remains in `(main)/layout.tsx`.
- Export a `config.matcher` that excludes `_next/static`, `_next/image`, and `favicon.ico` from middleware execution.

### Session API Route (`frontend/src/app/api/auth/session/route.ts`)
- `export async function GET()`.
- Read `draftvo_session` cookie via `cookies()` from `next/headers`.
- Call `verifyJwt(token)` from `@/lib/auth`.
- Return `NextResponse.json({ ok: true })` (200) if valid payload.
- Return `NextResponse.json({ ok: false }, { status: 401 })` if missing or invalid.

### AppLayout client guard (`frontend/src/app/_components/AppLayout.tsx`)
- Add a new `useEffect` (no dependencies `[]`) that:
  1. Defines `handlePageShow = async (event: PageTransitionEvent) => { if (event.persisted) { ... } }`.
  2. Inside the `if (event.persisted)` block: `fetch('/api/auth/session', { method: 'GET', cache: 'no-store' })`.
  3. If `!res.ok` → `window.location.replace('/login')`.
  4. Registers `window.addEventListener('pageshow', handlePageShow)`.
  5. Returns cleanup: `window.removeEventListener('pageshow', handlePageShow)`.

### Navigation (no change)
- Logout continues to use `window.location.replace('/login')` in `SettingsModal.tsx` — no change needed.
- Login continues to use `router.replace('/')` in `login/page.tsx` — no change needed.

### API / Session Data
- Cookie name: `draftvo_session` (from `SESSION_COOKIE` constant in `@/lib/auth`).
- Cookie presence check only in middleware (fast, no crypto).
- Full JWT signature + expiry check in `GET /api/auth/session`.
