## 1. Summary

Implement a functional, cache-persisted Theme selector in the settings modal. This will rely on `next-themes` to manage the dark/light state across the app, ensuring a flicker-free initial load by syncing with local storage and toggling a `.dark` CSS class.

## 2. Affected Screens & Components

- **[NEW]** `frontend/src/app/_components/ThemeProvider.tsx` — Next-themes provider wrapper required for client-side state in the App Router.
- **[MODIFY]** `frontend/src/app/layout.tsx` — To wrap the root `children` with `<ThemeProvider>`.
- **[MODIFY]** `frontend/src/app/globals.css` — To define the `.dark` class block and appropriate dark mode CSS variable overrides.
- **[MODIFY]** `frontend/src/app/_components/SettingsModal.tsx` — To wire up the Theme `<select>` to `useTheme()` provided by `next-themes`.
- **[MODIFY]** `frontend/package.json` — To add `next-themes` dependency.

## 3. User Flow (Step-by-Step)

1. User clicks the Gear icon in the sidebar to open `SettingsModal.tsx`.
2. User selects "Dark", "Light", or "System setting" from the Theme dropdown.
3. The `ThemeProvider` updates the `localStorage` preference and immediately toggles the `.dark` class on the `<html>` element.
4. The application styling updates globally to reflect the selected theme based on the CSS variables in `globals.css`.

## 4. Technical Requirements

### Data & State

- State is managed entirely by `next-themes` on the client.
- The `<select>` element must be bound to `theme` and `setTheme` from the `useTheme` hook.
- **Hydration Safety**: Because the server's guess of the theme won't match the client's `localStorage` on first render, the `SettingsModal.tsx` Theme selector must only render its actual value *after* the component has mounted (using a `useEffect` `isMounted` flag). Otherwise, React will throw a hydration mismatch error on the select option.
- Must add `suppressHydrationWarning` to the `<html>` tag in `layout.tsx` (the `<body>` already has it, but `next-themes` manipulates `<html>`).

### Navigation

- No routing changes required.

### API / Mock Data

- None. (Persisted to browser `localStorage`).

## 5. Design & UX Notes

- Ensure the CSS `.dark` variables override the default `:root` variables:
  ```css
  .dark {
    --background: #191919;
    --color-text-primary: #ffffff;
    --color-surface-muted: #2d2d2d;
    --color-surface-raised: #363636;
    --color-surface-base: #111111;
  }
  ```
- The toggle must feel instantaneous.

## 6. Hard Constraints (DO NOT CHANGE)

- Do not use Tailwind utility classes like `dark:bg-black` extensively; instead, rely on the CSS variables in `globals.css` since the project already has a token system (`var(--background)`, `var(--color-text-primary)`).
- Must use `next-themes` as explicitly audited by `/agent-grill`.
