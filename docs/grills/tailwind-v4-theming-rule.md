# Agent Rule: Tailwind v4 & Theming

> **Generated by `/agent-grill`**
> **Date:** 2026-08-20

## 1. Context & Architecture Audit

The project uses **Tailwind CSS v4** which introduces a "CSS-first" configuration (`@theme`) and removes `tailwind.config.js`. 
Recently, bugs were introduced where arbitrary classes like `border-[var(--color-surface-raised)]` failed to render correctly because Tailwind v4 does not parse them as colors unless explicitly told, or unless they are natively registered in the theme.

## 2. Identified Flaws & Resolutions

- **Flaw:** Agents using arbitrary variable syntax (e.g., `bg-[var(--color-bg)]`) which breaks compilation or produces unexpected defaults (like `currentColor`).
  **Resolution:** Enforce native utility usage (e.g., `bg-surface-raised`).

- **Flaw:** Adding new colors directly to inline classes or failing to define them in dark mode.
  **Resolution:** Agents must update `globals.css` (`:root`, `.dark`, and `@theme inline`) before using any new color.

- **Flaw:** Code churn from attempting to fix all legacy arbitrary classes at once.
  **Resolution:** Opportunistic refactoring. Agents will only fix arbitrary classes in the files they are actively editing.

## 3. Proposed Rule Implementation

We will create a new rule file at `.agents/rules/tailwind-v4.md` containing the following strict directives for all future agents:

### Rule Directives
1. **Never use arbitrary CSS variable classes** for colors (e.g., `❌ border-[var(--color-surface-raised)]`).
2. **Always use native v4 utilities** (e.g., `✅ border-surface-raised`).
3. **Adding New Colors:** If a new color is needed, the agent MUST first define it in `frontend/src/app/globals.css` across three places:
   - `:root` (Light mode)
   - `.dark` (Dark mode)
   - `@theme inline` (Tailwind v4 registration)
4. **Opportunistic Refactoring:** When editing a file, if the agent sees legacy arbitrary variable classes, they must convert them to native utility classes within that specific file only.
